## 2. What similarities exist among AWS, Azure, and GCP?

AWS, Microsoft Azure, and Google Cloud Platform (GCP) have many similarities because they all provide cloud computing services for businesses, developers, and organizations. While researching the three platforms, I noticed that they offer many of the same types of services, even though the names and specific features can be different.

For example, all three providers offer virtual machines. AWS has Amazon EC2, Azure has Azure Virtual Machines, and Google Cloud has Compute Engine. These services allow users to create virtual servers without having to purchase physical hardware. They also all provide object storage. AWS uses Amazon S3, Azure provides Azure Blob Storage, and Google Cloud provides Cloud Storage. These services can be used to store files, backups, images, videos, and application data.

Another similarity is that all three providers offer database services. AWS provides Amazon RDS, Azure provides Azure SQL Database, and Google Cloud provides Cloud SQL. They also have identity and access management services that allow administrators to control which users can access resources.

All three cloud providers also have global infrastructure. They have different regions and locations where organizations can deploy their applications. This helps businesses improve application performance and availability for users in different parts of the world.

Even though they are similar, each provider has its own strengths. AWS has a very large service portfolio, Azure is a good choice for organizations that use Microsoft products, and Google Cloud is especially strong in AI, machine learning, data analytics, and Kubernetes.

This activity helped me understand that the three platforms are competitors but also provide many similar solutions.

## 3. How do business requirements influence cloud platform selection?

Business requirements play a very important role when choosing a cloud provider. I learned from this mission that there is no cloud platform that is automatically the best choice for every company. Instead, the provider should be selected based on what the organization actually needs.

One important factor is the technology that a company already uses. For example, Client B in this activity was a university that already uses Windows Server, Microsoft 365, and Active Directory. In this situation, Microsoft Azure would be a good choice because it works well with Microsoft's existing technologies. Moving to Azure could make it easier for the university to manage its existing environment while gradually moving some services to the cloud.

Another example is Client C, the AI research company. This company needs high-performance computing for artificial intelligence and machine learning applications. Google Cloud would be a good option because of its strong AI, machine learning, data analytics, and Kubernetes services.

Budget is also important. A startup may not have enough money to purchase expensive hardware or maintain a large IT infrastructure. Using cloud services allows the startup to begin with the resources it needs and scale as the business grows.

Other factors include security, performance, availability, scalability, location, compliance, and the technical skills of employees. A global e-commerce company, for example, would need reliable infrastructure, automatic scaling, load balancing, and global availability.

Because of these differences, choosing a cloud provider requires careful analysis. A good cloud solution should solve the client's problem while also considering cost, security, performance, and future growth.

## 4. What did you learn from acting as a Cloud Solutions Consultant?

Acting as a Cloud Solutions Consultant taught me that working with cloud technology involves more than just knowing technical terms. A consultant needs to understand what a client wants to achieve and then determine which cloud services can help achieve those goals. This mission gave me an opportunity to think about cloud technology from a business perspective.

One of the biggest things I learned is that there is no single cloud provider that is perfect for everyone. AWS, Azure, and Google Cloud all have their own strengths. AWS has a very large selection of services, Azure is strongly connected to Microsoft technologies, and Google Cloud has strong capabilities in AI, machine learning, data, and Kubernetes.

I also learned how to compare equivalent services between cloud providers. For example, Amazon EC2, Azure Virtual Machines, and Google Compute Engine all provide virtual machine capabilities. Similarly, Amazon S3, Azure Blob Storage, and Google Cloud Storage provide object storage. Knowing these similarities makes it easier to compare cloud platforms.

The Linux investigation was also useful because it helped me connect what I already know about Linux servers with cloud computing. I used commands such as cat /etc/os-release, lscpu, free -h, and df -h to investigate the server. I then learned that the same type of Linux server could be hosted using Amazon EC2, Azure Virtual Machines, or Google Compute Engine.

Most importantly, I learned that recommendations should be based on facts and requirements. A consultant should not recommend a platform just because it is popular. The recommendation should explain why the platform is appropriate for the client's specific situation.
